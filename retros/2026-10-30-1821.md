## Suggestions
1. **Stuck ledger + stuck retro rule**: every stuck episode → a row in `retros/stuck-ledger.md` (where, signal, cause,
   fix, which earlier fix should have prevented it and did it); each stuck retro starts by reading the ledger and
   scoring earlier fixes. Repeated causes get a tool fix, not a doc note. *Low.*
2. **Plan check before walking**: `./wf plan <place>` first; any never-walked segment > 8 units or through a red X is
   a warning to ask `./wf ask-step` before walking. (Planner now penalises these, L74.) *Done in code.*
3. **One game command per tool call** (never `stop; resume; goto` together), and after any rejected call check
   `tail .shots/actions.log` + pause. ~2 lost game hours → 0. *Behavioural.*
4. **Stuck = < 2 units over 3 moves** (user rule) decides when to ask vision; one failed step only marks a wall. *Done, L75.*
5. **Count stuck per trip** in `./wf learn nav` (episodes, refused clicks, vision asks/answers walked) so the next
   retro compares numbers, not impressions. *Low.*
